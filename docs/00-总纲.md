## 0. 这份文档解决什么问题

你在用 Rust 写 Windows 桌面软件,遇到的核心矛盾是:

1. **Rust 没有现成的"设计软件级" UI 库** —— 现有框架要么太通用(按钮表单型),要么太底层(裸渲染);
2. **设计软件对 UI 的要求远超普通桌面应用** —— 无限画布、贝塞尔编辑、图层树、时间轴、Dock 面板、GPU 实时预览,每一项都是硬骨头;
3. **重复造轮子 vs 站在巨人肩膀** —— 需要明确哪些轮子直接用、哪些轮子改造、哪些必须自研。

本套手册(1 总册 + 6 分册)给出一个可落地的完整答案:**一个具体的技术栈选型、一个自研前端库(Lumina UI)的完整设计、可直接编译的代码骨架、以及分阶段迭代路线图。**

与最初设计文档不同的是:这套手册现在是**本仓库的活文档** —— v0.1 的 `lumina-core` / `lumina-paint` 已经按分册二/三/六的设计落地,各分册尾部带"实现状态表",逐条标注 已实现(给 `crate::module` 路径)/ 进行中 / 规划。

## 1. 调研结论速览(TL;DR)

### 1.1 生态格局(2026 年实测)

2026 年 7 月有团队用**同一个 App 规格**实测了 7 大框架(rust-gui-desktop-ecosystem-state 项目),关键结论:

| 框架 | 渲染模式 | 冷编译 | 二进制 | 特点 | 对设计软件的适配度 |
|---|---|---|---|---|---|
| **GPUI** (0.2.2) | 混合即时/保留,GPU | 56s | 5.0 MiB | Zed 编辑器同款引擎,120 FPS | ★★★★★ |
| **egui** (0.35) | 纯即时模式,wgpu | 27s | 12 MiB | 最成熟、生态最大、迭代快 | ★★★★ |
| **iced** (0.14) | Elm 架构,wgpu | 22s | 9.9 MiB | 架构优雅,组件生态弱 | ★★★ |
| **Slint** (1.17) | DSL 声明式 | 42s | 14.7 MiB | 嵌入式强,商业许可注意 | ★★ |
| **Xilem** (0.4) | 函数响应式,Vello | 28s | 11.4 MiB | Linebender 出品,alpha | ★★★ |
| **Dioxus** (0.7) | React 风格,WebView/Blitz | 40s | 5.7 MiB | 跨端复用 | ★★ |
| **Tauri** (2.11) | 系统 WebView | 36s | 8.0 MiB | 前端技术栈友好 | ★★ |

### 1.2 核心选型结论

**主栈(已锁定):GPUI + gpui-component + Vello + Kurbo,自研 Lumina 作为"画布内核 + 设计软件专用组件层"。**

理由:
- **GPUI 是为"编辑器类软件"而生的** —— Zed 用它做到 120 FPS,混合即时/保留模式天然契合"面板 UI(保留)+ 画布(即时)"的双模需求;
- **gpui-component 填补了组件空白** —— Longbridge(长桥证券)生产环境验证,60+ 组件含 **Dock 布局、虚拟化表格/列表、颜色选择器、代码编辑器、图表**,Apache 2.0 许可,正好覆盖设计软件的"面板系统";
- **Vello + Kurbo 是矢量渲染的事实标准** —— Linebender 出品,GPU 计算管线渲染贝塞尔曲线,Graphite(开源 Illustrator 替代品)同源技术;
- **Windows 已可用** —— 本仓库锁定 gpui 0.2.2(crates.io),Windows MSVC 全栈可编译(2026-10-02 本机探针验证)。IME 支持尚在完善(做中文输入的属性框需关注,见 [06-鲁棒性与技术债.md](06-鲁棒性与技术债.md) TD-03)。

**备选栈(快速原型/求稳):egui + egui_dock + epaint 自绘画布。** egui 跨平台最成熟,Windows 无障碍/IME 最稳,但复杂面板 UI 开发效率和美观度不如 GPUI 栈。

**视频剪辑模块参考:Gausian(Rust 原生视频编辑器)** —— 其 WGPU 预览管线(YUV→RGB shader)、时间轴架构、SQLite 项目持久化、FCPXML 导出都是可直接抄作业的成熟设计。此外,本仓库的直接宿主应用 **CutForge**(视频剪辑内核)是 lumina-dock + lumina-video 的第一个验收场,见 [upstream/01-cutforge-ui-analysis.md](upstream/01-cutforge-ui-analysis.md)。

## 2. Lumina UI 总体设计

### 2.1 命名与定位

- **名字**:Lumina UI(流明)—— 寓意光与色彩,契合设计软件
- **定位**:不是又一个通用 UI 框架,而是**"创作工具专用 UI 库"**(Creative Tool UI Kit)
- **一句话**:GPUI 负责窗口与面板,Vello 负责画布,Lumina 把它们粘合成 Illustrator/剪映能用的东西

### 2.2 分层架构(六层 + L0 基础层)

```
┌─────────────────────────────────────────────────────┐
│ L6 应用层    你的软件(矢量设计模块 / 视频剪辑模块)      │
├─────────────────────────────────────────────────────┤
│ L5 Lumina 专用组件层  画布视图/图层面板/时间轴/属性       │
│   (lumina-widgets)  检查器/颜色井/节点图/标尺/参考线      │
├─────────────────────────────────────────────────────┤
│ L4 面板系统    Dock 布局/工具栏/菜单/快捷键/命令面板      │
│   (gpui-component 0.7.0 + lumina-dock)                 │
├─────────────────────────────────────────────────────┤
│ L3 画布内核    命中测试/网格/脏矩形/LOD/工具/渲染调度     │
│   (lumina-canvas)                                     │
├─────────────────────────────────────────────────────┤
│ L2 渲染层      Vello (GPU 2D) / vello_cpu (CPU 兜底)   │
│   (lumina-paint)  Kurbo (曲线) / Parley (文本) / wgpu   │
├─────────────────────────────────────────────────────┤
│ L1 平台层      GPUI (窗口/事件/状态) / winit            │
├─────────────────────────────────────────────────────┤
│ L0 基础层      视口变换/场景图(纯数据)/命令系统(撤销重做)│
│   (lumina-core)  原子写持久化 —— 零 UI 框架依赖          │
└─────────────────────────────────────────────────────┘
```

> **2026-10 落地决策**:Scene 场景图从 lumina-canvas **下沉进 lumina-core**(详见 [02-渲染与画布.md](02-渲染与画布.md) §3)。原因:命令系统必须能命名被编辑状态,而 Scene 是纯数据(kurbo/slotmap/serde 全在 core 的零 UI 依赖白名单内);canvas 保留行为层(hit_test/grid/damage/lod/tool/render)。上图中 L3 的职责已据此调整。

### 2.4 关键设计决策(为什么是这些轮子)

| 决策点 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 窗口/事件/面板框架 | **GPUI 0.2.2**(crates.io) | egui | 编辑器基因、GPU 原生、组件生态(gpui-component) |
| 现成组件库 | **gpui-component 0.7.0**(crates.io,仓库已改名 gpui-kit) | 自研 | 60+ 生产级组件,Dock/虚拟列表/颜色选择器现成 |
| 布局引擎 | **Taffy**(GPUI 内置) | morphorm | flexbox+grid,Servo/Bevy 同款,生态收敛点 |
| 2D 矢量渲染 | **Vello 0.10** | tiny-skia/lyon | GPU 计算管线,贝塞尔原生,性能天花板 |
| CPU 回读/兜底 | **vello_cpu 0.2** | tiny-skia | 截图导出、无 GPU 环境、渲染回归测试(已实现,见 [02-渲染与画布.md](02-渲染与画布.md)) |
| 曲线几何 | **Kurbo 0.13.1** | 自研 | 贝塞尔求交/偏移/欧拉螺线描边扩展,工业级 |
| 样式原语 | **Peniko 0.6.1** | 自研 | 与 Vello/Kurbo 配套(Color/Gradient/Brush);**core 场景图不用它**(自有 `Paint` 枚举,serde 友好,见分册二 §3) |
| 文本 | **Parley 0.11 + HarfRust** | cosmic-text | Linebender 栈,与 Vello 天然集成 |
| 窗口互操作 | winit(GPUI 内部) | — | 4/7 框架的收敛层 |
| 无障碍 | **AccessKit** | — | Windows UI Automation 对接(TD-04,M0 纪律) |
| 图像编解码 | image 0.25 | — | PNG/JPEG/WebP |
| SVG 导入 | resvg + usvg | — | 对接 Illustrator 工作流(M2 接入,未锁定版本) |
| 视频解码 | ffmpeg-next / gstreamer-rs | — | 剪映模块,参考 Gausian(M4 起,遵守 TD-11 LGPL 纪律) |
| 项目持久化 | 原子写(tmp+fsync+rename)已实现;SQLite(rusqlite)为 Gausian 参考方案 | sled | 崩溃不丢稿是底线(已实现,`lumina-core::persistence`) |
| 撤销重做 | 命令模式(自研 lumina-core)✅ 已实现 | — | 设计软件核心,必须自研(含 IdRemap 治愈,见分册三 §2) |

## 5. 最小可运行验证(M0 预览,版本已按 2026-10 锁定修正)

以下是 M0 的完整 `Cargo.toml` 依赖面(与本仓库 workspace 根一致):

```toml
[dependencies]
# GPUI 主框架(Zed 出品,0.2.2 已上 crates.io —— 不再需要 git 依赖)
gpui = "0.2.2"

# Longbridge 生产级组件库:Dock/按钮/颜色选择器/虚拟列表等 60+ 组件
# (GitHub 仓库已改名 longbridge/gpui-kit,crate 名仍为 gpui-component;0.7.0 上 crates.io)
gpui-component = "0.7.0"

# 矢量渲染三件套(Linebender 栈,2026-10 锁定)
vello = "0.10.0"
kurbo = "0.13.1"
peniko = "0.6.1"
```

```rust
// src/main.rs —— M0:一个带 Dock 面板和画布区域的空壳
// (骨架示意;落地时以 gpui 0.2.2 / gpui-component 0.7.0 的 docs.rs 实际签名为准)
use gpui::*;
use gpui_component::{dock::{DockArea, DockItem}, Root};

fn main() {
    Application::new().run(|cx: &mut App| {
        gpui_component::init(cx);
        cx.open_window(WindowOptions::default(), |window, cx| {
            let dock = cx.new(|cx| {
                let area = DockArea::new("main-dock", Some(1), window, cx);
                // 左侧:图层面板 / 中间:画布 / 右侧:属性检查器
                // 详见 04-专用组件.md §1、§2
                area
            });
            let view = cx.new(|_| MainView { dock });
            cx.new(|cx| Root::new(view.into(), window, cx))
        })
        .expect("open window failed");
    });
}

struct MainView {
    dock: Entity<DockArea>,
}

impl Render for MainView {
    fn render(&mut self, _: &mut Window, _: &mut Context<Self>) -> impl IntoElement {
        div().size_full().child(self.dock.clone())
    }
}
```

> 相比原设计文档的修正:①`gpui` / `gpui-component` 全部走 crates.io 版本,删除 git 依赖与 `gpui_platform`;②Linebender 栈版本从 vello 0.5 / kurbo 0.11 / peniko 0.4 升到 vello 0.10 / kurbo 0.13.1 / peniko 0.6.1;③入口从 `gpui_platform::application()` 改为 gpui 0.2 的 `Application::new().run(...)`。本仓库 lumina-dock 的 Cargo.toml 已按此接好依赖。

跑通这个壳子之后,按 [02-渲染与画布.md](02-渲染与画布.md) 把 Vello 画布填进中间区域,按 [04-专用组件.md](04-专用组件.md) 填充两侧面板,就进入了正式迭代。
