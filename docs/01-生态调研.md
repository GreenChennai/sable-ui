## 1. 生态分层地图

Rust GUI 生态在 2026 年已经**从碎片化走向分层收敛**。理解这张图,选型就完成了一半:

```
应用框架层:  GPUI   egui   iced   Slint   Xilem   Vizia   Floem   Makepad   Dioxus   Tauri
                │      │      │      │       │      │       │        │         │        │
组件库层:   gpui-component  egui_dock/egui_node_graph  iced_aw  slint-widgets ...
                │      │      │      │       │      │       │        │         │        │
布局层:         taffy(flexbox+grid,GPUI/Floem/Servo/Blitz 采用)  morphorm(Vizia)  iced 自研
                │      │      │      │       │      │       │        │         │        │
渲染层:      wgpu ──┬── Vello(GPU 2D 计算渲染)
                    ├── epaint(egui 的绘制层)
                    ├── femtovg / tiny-skia / Skia
                    └── blade(GPUI 曾用,已回归 wgpu)
                │
窗口层:      winit(egui/iced/slint/xilem 4 家共用)  tao(winit fork,Tauri/Dioxus)
                │
无障碍层:    AccessKit(egui/slint/xilem 已集成)
                │
文本层:      Parley/HarfRust ・ cosmic-text ・ swash/skrifa/fontdb
```

**关键洞察:生态的"收敛点"是 winit(窗口)、taffy(布局)、wgpu(GPU)、AccessKit(无障碍)、Linebender 栈(Vello/Kurbo/Parley,2D 矢量与文本)。** 自研库站在这些收敛点上,就不用自己造基础设施。

## 2. 候选框架逐一评估

### 2.1 GPUI —— 最终主选 ★★★★★

- **仓库**:`zed-industries/zed`(crates/gpui),2025-10 发布 0.2.0 至 crates.io,**本仓库锁定 0.2.2**
- **背景**:Zed 编辑器自研 UI 框架,Zed 团队为"120 FPS 编辑器"从零打造;2026-05 Zed 1.0 发布,GPUI 随之稳定
- **渲染模型**:**混合即时/保留模式** —— View 树是保留的(Entity 持有状态),每帧的绘制指令是即时的。这正好匹配设计软件:面板 UI 要状态(保留),画布要高频重绘(即时)
- **GPU 后端**:macOS Metal,Windows/Linux 经 wgpu(2026-02 Zed main 已切 wgpu;**注意:Windows 上 GPUI 发行版仍是 DirectX 11 原生渲染器**,对 Lumina 画布桥接的影响见 [06-鲁棒性与技术债.md](06-鲁棒性与技术债.md) §6.2)
- **API 风格**:Tailwind 式链式调用 `div().flex().items_center().bg(rgb(0x505050))`
- **布局**:内置 Taffy(flexbox + grid)
- **无障碍**:AccessKit 集成已合并(2026-05,zed#56065)
- **实测**:冷编译 56s(7 框架最慢,因依赖树 391 crates),但增量编译 1s,二进制仅 5.0 MiB(7 框架最小)
- **本仓库验证**:gpui 0.2.2(crates.io)在 Windows MSVC 全栈可编译(2026-10-02 本机探针)
- **⚠️ Windows 风险**:macOS 一等公民;Windows 可运行但 **IME(中文输入法)支持尚粗糙**(zed#40300、#41881)。做中文属性输入框需跟踪此问题,缓解方案见 [06-鲁棒性与技术债.md](06-鲁棒性与技术债.md) TD-03
- **⚠️ 2026-02 社区动态**:Zed 官方宣布暂停 GPUI 社区向工作("focus on business relevant work"),社区 fork `gpui-ce` 已出现但落后主线约 381 commits。GPUI 的 Windows 渲染器为 DirectX 11 原生(仅 Linux 迁往 wgpu)。应对策略见 [06-鲁棒性与技术债.md](06-鲁棒性与技术债.md) TD-02 与 §6
- **生态加分项**:`gpui-component`(Longbridge)提供 60+ 生产级组件
- **上游印证**:CutForge 的桌面壳(apps/desktop)正是因"GPUI 0.2.2 生态尚在演进"被 ADR 降级为观察项 —— Lumina 与它共担同一赌注,复活条件(GPUI 稳定版 + Windows 冒烟)直接抄为 Lumina M3 验收门槛,见 [upstream/01-cutforge-ui-analysis.md](upstream/01-cutforge-ui-analysis.md) §4

```rust
// GPUI 核心编程模型:Entity(状态) + Render trait(视图)
pub trait Render: 'static + Sized {
    fn render(&mut self, window: &mut Window, cx: &mut Context<'_, Self>)
        -> impl IntoElement;
}

// 状态更新 → 通知重绘
impl CanvasView {
    fn add_shape(&mut self, shape: Shape, cx: &mut Context<Self>) {
        self.document.shapes.push(shape);
        cx.notify(); // 触发重绘
    }
}
```

### 2.2 egui —— 备选/原型首选 ★★★★

- **仓库**:`emilk/egui`,当前 0.35,**生态最大、迭代最快**的纯 Rust GUI
- **模式**:纯即时模式(immediate mode)—— 每帧重建整个 UI,没有状态同步问题,心智负担最低
- **优势**:Windows/macOS/Linux/Web 全平台最成熟;IME 自 0.28 起支持,0.35 有完善的 preedit 视觉;AccessKit 已集成;编译快、文档全
- **设计软件适配**:`epaint` 绘制层可直接画贝塞尔/网格;`egui_dock`(Dock 布局)、`egui_node_graph`(节点图)、`egui_plot` 现成;Rerun(数据可视化工具)证明了它能做复杂创作工具;**VellumBench(本仓库的设计语义供体)就在 egui 0.35 上用自研 vb_ui 做出了完整的令牌体系与组件层** —— 见 [upstream/02-vellumbench-ui-analysis.md](upstream/02-vellumbench-ui-analysis.md)
- **短板**:超复杂面板 UI(多级 Dock + 虚拟化大列表 + 自绘混排)时开发效率和颜值不如 GPUI 栈;文本段落级 BiDi 缺失(egui#1016)
- **结论**:**3 天出原型用它,正式产品用 GPUI**。两套栈的画布内核(L0/L2/L3 层)可以共用

### 2.3 iced —— 架构最优雅 ★★★

- Elm 架构(Model-View-Update),wgpu 渲染,0.14(2025-12)落地 IME(cosmic-text)
- 组件生态弱,Dock/画布类组件基本要自研;适合表单型应用,不适合设计软件主力
- **可借鉴**:其 `widget::canvas` 的"几何缓存"设计(把绘制结果缓存成 Geometry,避免每帧重算)值得 Lumina 画布借鉴

### 2.4 Slint ★★(许可注意)

- DSL 声明式语言,编译型 UI,嵌入式/工业 HMI 强;1.17 起实验性嵌入 taffy
- **许可陷阱**:GPLv3 / 付费商业许可 / Royalty-free(有限制)三选一,闭源商业软件基本要付费
- 设计软件的自由画布场景非其所长,pass

### 2.5 Xilem ★★★(观望)

- Linebender 出品的架构实验品(前身 Druid),直接构建在 Vello 之上
- 如果它成熟,是"Vello 原生 UI 框架"的最优解;但当前 alpha,API 不稳定
- **策略**:保持关注,Lumina 的 L0/L2/L3 层(数据/渲染/画布)与其技术栈完全同源,未来可迁移

### 2.6 其余快速结论

| 框架 | 一句话结论 |
|---|---|
| **Dioxus 0.7** | React 风格跨端(桌面/Web/移动同码),Blitz 原生渲染在演进;团队协作型产品可考察,单体重度创作软件不首选 |
| **Tauri 2.11** | WebView 壳,适合"前端团队 + Rust 后端";重度 GPU 画布在 WebView 里可用 WebGPU 但工程割裂,不选 |
| **Vizia** | CSS 风格样式系统有想法,但小众、morphorm 布局单家使用,风险高 |
| **Floem** | Lapce 编辑器出品,Vello+taffy 栈与选型同源但完成度低于 GPUI 生态 |
| **Makepad** | 自研着色器 DSL 很有野心(VR/设计工具演示惊艳),但生态极小、文档稀缺,单人项目勿入 |
| **gtk-rs/qt-rs** | C++ 依赖链与 Windows 打包复杂度高,与"纯 Rust"目标冲突 |

## 3. 组件库与专用轮子评估

### 3.1 gpui-component / gpui-kit(Longbridge)—— 必用

- **crate**:`gpui-component` **0.5.1,已上 crates.io —— 本仓库直接版本锁定,无需 git 依赖**(0.6+ 不兼容,见 docs/03 §6.1)
- **仓库**:`longbridge/gpui-component`(**已改名 `gpui-kit`**,crate 名不变;75+ 组件)
- **背景**:长桥证券的交易终端 Longbridge Pro 从第一天就构建其上 —— **公开上市的商业桌面软件验证**
- **对设计软件直接可用的组件**:
  - **DockArea**:可拖拽分割面板、Tab、嵌套 Dock、可序列化布局 → 图层面板/属性面板/素材库的布局系统
  - **Table/List(虚拟化)**:数十万行流畅滚动 → 图层列表、素材列表、字幕列表
  - **ColorPicker**:颜色选择器 → 直接复用
  - **Slider/Input/Select/Dialog/Menu/Tooltip/Popover**:属性检查器的全部基础件
  - **Theme/ThemeColor**:语义化多主题 → 设计软件的深色/浅色主题
  - **Chart**:曲线图 → 速度曲线、音量包络可改造
- **许可**:Apache 2.0(设计基于 shadcn/ui,图标 Lucide)
- **用法**(本仓库 lumina-dock 已按此接好依赖):

```toml
gpui           = "0.2.2"
gpui-component = "0.7.0"
```

```rust
use gpui_component::{button::*, slider::Slider, color_picker::ColorPicker, dock::*};
// 必须在使用任何组件前初始化
gpui_component::init(cx);
```

### 3.2 Vello —— 矢量渲染内核 ★★★★★

- **仓库**:`linebender/vello`,**本仓库锁定 0.10.0**
- **定位**:GPU 计算管线的 2D 渲染引擎,对标 Skia/Cairo,但把光栅化全部搬进 GPU compute shader
- **技术原理**:PostScript 式路径 → GPU 端曲线展平/排序/tile 化 → 每像素列表渲染。贝塞尔曲线的填充/描边、渐变、混合、剪辑全部 GPU 并行
- **描边扩展**:基于欧拉螺线(Euler spiral)的 GPU 友好描边算法(SIGGRAPH 2024 论文),一条大曲线 1-2 段三次贝塞尔即可逼近偏移曲线
- **vello_cpu 0.2**:CPU 渲染变体(状态机式 API:set_paint/set_transform + fill_path/stroke_path),用于导出 PNG、缩略图、无 GPU 兜底与**渲染回归测试**;注意其输出为**预乘 alpha 的 RGBA8**(本仓库 `lumina-paint::cpu` 已封装并验证,见 [02-渲染与画布.md](02-渲染与画布.md) 实现状态表)
- **在设计软件中的角色**:Illustrator 式矢量内容的最终绘制者;剪映式文字贴纸/矢量图形的绘制者

### 3.3 Kurbo —— 曲线几何库 ★★★★★

- **仓库**:`linebender/kurbo`,**本仓库锁定 0.13.1**(serde feature 开)
- **能力**:贝塞尔曲线求值/求交/分割/偏移(offset)、路径布尔运算基础、欧拉螺线、仿射变换
- **设计软件的一切矢量操作都靠它**:钢笔工具的曲线拟合、轮廓化描边、路径裁剪、形状布尔(联集/交集/差集 —— 配合 `i-float` 做布尔运算)
- **API 速览**:

```rust
use kurbo::{BezPath, Point, PathEl, Affine, CubicBez};

// 构造一条三次贝塞尔路径
let mut path = BezPath::new();
path.move_to((100.0, 100.0));
path.curve_to((150.0, 50.0), (250.0, 50.0), (300.0, 100.0));
path.close_path();

// 仿射变换(画布缩放平移本质就是 Affine)
let affine = Affine::translate((10.0, 20.0)) * Affine::scale(2.0);
let transformed = affine * &path;

// 曲线求交(钢笔工具吸附、形状布尔的基础)
let c1 = CubicBez::new((0.,0.), (30.,90.), (70.,90.), (100.,0.));
let c2 = CubicBez::new((0.,50.), (30.,-40.), (70.,-40.), (100.,50.));
for hit in c1.intersections(&c2) {
    println!("交点: {:?}", c1.eval(hit.t));
}
```

> kurbo 0.13 注意点(本仓库实测):`Affine` **没有 `Mul<Rect>`**,包围盒变换用 `Affine::transform_rect_bbox`;`Affine::translate` 接受任何 `Into<Vec2>`。场景图代码里已有对应适配(`lumina-core/src/scene.rs`)。

### 3.4 Parley + HarfRust —— 文本

- Linebender 文本栈(**本仓库锁定 parley 0.11.1**):Parley 做段落布局(对齐/换行/行距),HarfRust 做 shaping(OpenType 特性/连字/复杂文字)

## 4. 参考成品项目深度剖析

### 4.1 Zed(GPUI 的亲爹)

- **学什么**:`crates/gpui/src` 的 Entity/Context/Render 模型;`workspace` crate 的面板管理;异步任务与 UI 的集成(`cx.spawn`)
- **抄作业点**:编辑器面板(Panel trait)设计 ≈ 设计软件的"可停靠面板"协议;命令面板 ≈ 设计软件的动作搜索(Illustrator 没有但剪映类软件的趋势)

### 4.2 Graphite(开源 Illustrator 替代)

- **仓库**:`GraphiteEditor/Graphite`,Rust + WebAssembly + WebGPU,Vello 渲染
- **学什么**:
  - **节点图文档模型**:所有编辑操作都是节点,天然非破坏性 —— 比 Illustrator 的"图层+效果栈"更先进,可参考其消息驱动架构(`Editor → Message → Document`)
  - 工具系统(Tool trait:钢笔/选择/渐变…每个工具一个状态机)—— Lumina 的 `ToolBehavior` 设计来源(见 NOTICE.md 登记)
  - SVG 导入导出
- **注意**:它是 Web 优先架构,桌面版为 WASM 壳,工程结构仅供参考思想而非直接复用代码

### 4.3 Gausian(开源剪映雏形)

- **仓库**:`gausian-AI/Gausian_native_editor`
- **学什么**:
  - WGPU 预览管线:解码帧 → YUV 纹理 → shader 转 RGB → 上屏 + 读回
  - 时间轴编辑、素材面板、SQLite 项目持久化
  - 导出器:FCPXML 1.9/1.10、FCP7 XML、EDL —— 与剪映/Pr/FCP 工程互通的关键
  - 代理生成(大文件剪辑流畅的秘诀)
- **结论**:剪映模块照它的架构抄,UI 层换成 Lumina。**国内对照物:CutForge 内核已完成多轨时间线/OpLog/撤销栈工程化,是更近的参照与宿主**(见 [upstream/01-cutforge-ui-analysis.md](upstream/01-cutforge-ui-analysis.md))

### 4.4 Longbridge Pro(闭源,看形态)

## 5. 选型决策矩阵(加权评分)

评分维度权重(设计软件视角):渲染性能 25%、组件完备度 20%、Windows 成熟度 15%、API 生产力 15%、许可与可持续 15%、生态/文档 10%。

| 方案 | 渲染 | 组件 | Windows | 生产力 | 许可 | 生态 | 加权总分 |
|---|---|---|---|---|---|---|---|
| **GPUI + gpui-component + Vello** | 9.5 | 8.5 | 7.5 | 8.5 | 10 | 8 | **8.7** ✅ |
| egui + egui_dock + 自绘 | 7.5 | 7 | 9.5 | 9 | 10 | 9.5 | 8.6 |
| iced + 全自研组件 | 8 | 5 | 9 | 7 | 10 | 7 | 7.5 |
| Xilem(Vello 原生) | 9.5 | 4 | 7 | 6 | 10 | 6 | 7.3 |
| Slint | 7 | 7 | 9 | 7 | 5 | 7 | 7.0 |
| Tauri + 前端框架 | 6 | 9 | 9 | 9 | 10 | 9 | 8.4* |

\* Tauri 分数高但"纯 Rust 技术栈"目标不符,且 WebView 内做重度 GPU 画布(WebGPU)与 Rust 侧数据通路工程复杂,故不推荐。

**最终决策(已执行):GPUI + gpui-component + Vello + Kurbo 为主栈,egui 为快速原型/兜底副栈。**
