## 1. 图层面板 LayerPanel

**设计要点**:虚拟滚动(万级图层)、拖拽排序、缩略图、眼睛/锁、双击改名。

```rust
pub struct LayerPanel {
    doc: Entity<Document>,
    list: UniformListState,          // gpui 的虚拟化列表状态
    dragging: Option<NodeId>,
}

impl Render for LayerPanel {
    fn render(&mut self, window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        let rows = self.doc.read(cx).scene.roots.clone(); // 拍平后的可见行
        v_flex().size_full()
            // 工具行:新建图层/新建组/删除
            .child(self.toolbar(cx))
            // 虚拟化列表:万级图层不卡(gpui uniform_list)
            .child(uniform_list(cx.entity().clone(), "layers", rows.len(),
                move |panel, range, _w, cx| {
                    range.map(|ix| panel.layer_row(rows[ix], ix, cx)).collect()
                })
                .size_full())
    }
}

fn layer_row(&self, id: NodeId, ix: usize, cx: &Context<Self>) -> impl IntoElement {
    let doc = self.doc.read(cx);
    let node = doc.scene.node(id).expect("行 id 来自场景快照,必然存活");
    let selected = doc.selection.contains(&id);
    h_flex()
        .id(("layer", ix))
        .h(tokens.row_height())   // 控件高度:三档下限 + 行高派生(分册六 §3)
        .px_2().gap_2().items_center()
        .when(selected, |el| el.bg(tokens.accent_muted))
        // 可见性
        .child(eye_toggle(node.visible, cx.listener(move |this, _, _, cx| {
            this.doc.update(cx, |d, cx| {
                let old = d.scene.node(id).expect("存活").visible;
                d.history.exec(SetVisibility { id, old, new: !old }.boxed(), &mut d.scene);
            });
        })))
        // 缩略图:vello_cpu 离屏渲染 16x16,缓存按 node 版本号失效
        .child(LayerThumb::new(id))
        // 名字(双击进入编辑)
        .child(div().flex_1().child(node.name.clone()))
        .on_click(cx.listener(move |this, ev, _, cx| {
            this.doc.update(cx, |d, _| d.select(id, ev.modifiers().shift));
            cx.notify();
        }))
}
```

> 缩略图策略:每个可见节点维护 `(node_version, Pixmap)` 缓存,版本号不变直接用图 —— 这是"万图层不卡"的关键之一,配合虚拟列表只渲染可见行。渲染用 `sable_paint::cpu::CpuRenderer`(已实现,输出预乘 RGBA8)。
> 拖拽排序走 `Reparent` 命令(已实现,含成环检测),天然可撤销。

## 3. 钢笔工具 PenTool(贝塞尔编辑核心)

**状态机**(Illustrator 钢笔行为全集):

```
Idle ──点击──▶ 锚点(直角) 持续拖动 ──▶ 拖出双向手柄(平滑点)
  │点击已有锚点──▶ 删除锚点 / 转直角
  │点击路径端点──▶ 续接路径
  │点击起点────▶ 闭合路径 → 生成 AddPath 命令
  │Alt拖手柄──▶ 单边手柄(尖点)
```

```rust
pub struct PenTool {
    draft: BezPath,                  // 绘制中的路径草稿
    cur_anchor: Option<Point>,
    cur_handle: Option<Point>,       // 拖出的手柄
    hover: PenHover,                 // 悬停命中(起点/锚点/线段)
}

impl ToolBehavior for PenTool {
    fn mouse_down(&mut self, pt: Point, mods: Modifiers, doc: &mut Document) {
        match self.hover {
            PenHover::StartAnchor if self.draft.elements().len() > 2 => {
                self.draft.close_path();          // 闭合 → 完成
                self.commit(doc);
            }
            PenHover::Endpoint => { /* 续接已有路径 */ }
            _ => {
                self.cur_anchor = Some(pt);       // 新锚点,等 drag 决定是直角还是平滑
                self.cur_handle = None;
            }
        }
    }

    fn mouse_drag(&mut self, pt: Point, doc: &mut Document) {
        if let Some(anchor) = self.cur_anchor {
            self.cur_handle = Some(pt);           // 拖出手柄 → 平滑点
        }
    }

    fn mouse_up(&mut self, doc: &mut Document, history: &mut History) {
        let Some(anchor) = self.cur_anchor.take() else { return };
        match self.cur_handle.take() {
            None => self.draft.line_to(anchor),   // 直角点
            Some(h) => {
                let mirror = anchor + (anchor - h); // 镜像手柄
                self.draft.curve_to(mirror, h, anchor); // 简化:实际需存 prev_handle
            }
        }
    }

    /// 预览层:草稿路径 + 橡皮筋线(随鼠标实时弯;覆盖层,屏幕等宽描边)
    fn preview(&self, sink: &mut impl PaintSink, vp: &Viewport) {
        let stroke = StrokeStyle { paint: tokens.pen_preview(), width: 1.0 / vp.zoom };
        sink.stroke(&stroke, vp.world_to_viewport(), &self.draft);
        // 从最后一个锚点到鼠标的实时贝塞尔预览(略)
    }
}
```

> **曲线拟合**:手绘板/铅笔工具的"涂鸦→光滑路径"用 kurbo 的 `fit_to_bezpath`(简化容差可调),1 行搞定 Inkscape 级拟合。
> 提交纪律:闭合瞬间把草稿包进 `AddNode`(已实现的命令)进 History,预览期间**不产生任何文档修改**。

## 4. 色轮 ColorWheel + 色井 ColorWell

**设计**:HSL 色轮(GPU 绘制,一个 shader/或 vello 渐变近似),外圈色相 + 内三角饱和度/明度(Photoshop 式)或方盘(Figma 式)。

```rust
pub struct ColorWheel {
    binding: Binding<Rgba8>,
    drag_target: Option<WheelPart>,   // Ring | Triangle
}

impl ColorWheel {
    /// 每帧绘制(60fps 连续拖也不贵:一张 256px 离屏纹理 + 拾取颜色数学)
    fn paint(&mut self, bounds: Bounds, window: &mut Window, cx: &mut App) {
        let center = bounds.center();
        let c = self.binding.get(cx);
        // 1. 外环:用缓存的色相环纹理(按明度重着色,尺寸变化才重建)
        window.paint_image(self.hue_ring_cache(c), bounds);
        // 2. 内三角/方盘:HSV 平面,vello 三角渐变或预渲染纹理
        window.paint_image(self.sv_disk_cache(c), inner_bounds(bounds));
        // 3. 手柄:当前色位置画小圆
        let (x, y) = sv_to_xy(c, inner_bounds(bounds));
        window.paint_quad(fill(circle_bounds(x, y, 6.), tokens.anchor_selected()));
    }

    fn on_drag(&mut self, pos: Point, cx: &mut Context<Self>) {
        let mut c = self.binding.get(cx);
        match self.drag_target {
            Some(WheelPart::Ring) => { c = hue_at_angle(pos, self.center, c); }
            Some(WheelPart::Triangle) => { c = sv_at_xy(pos, self.inner, c); }
            None => return,
        }
        (self.binding.set)(c, cx);   // → SetFill 命令 → 可撤销(连续拖由 merge 合并成一步)
    }
}
```

> **偷懒方案**:色轮静态部分画一次进 wgpu 纹理缓存;拖动只重画手柄层。128x128 纹理足够,缩放用线性过滤。
> 颜色类型纪律:组件层对外的 `Binding` 用 `Rgba8`(场景图类型,serde 直出);转 `peniko::Color` 走 `sable_paint::style::to_color`(已实现)。

## 6. 数值拖拽框 NumberField(设计软件的灵魂小件)

Illustrator 用户最依赖的输入方式:鼠标按住标签左右拖直接改值。

```rust
pub struct NumberField {
    binding: Binding<f64>,
    range: RangeInclusive<f64>,
    step: f64,              // 默认 1.0;Shift ×10;Alt ×0.1
    unit: SharedString,     // "px" / "%" / "°"
    drag_start: Option<(Point, f64)>,
    editing: Option<TextInput>,   // 单击进入文本编辑态
}

impl NumberField {
    fn on_label_drag(&mut self, pos: Point, cx: &mut Context<Self>) {
        let Some((start_pt, start_val)) = self.drag_start else { return };
        let dx = pos.x - start_pt.x;
        let mods = cx.modifiers();
        let scale = if mods.shift { 10.0 } else if mods.alt { 0.1 } else { 1.0 };
        let v = (start_val + dx * self.step * scale).clamp(*self.range.start(), *self.range.end());
        (self.binding.set)(v, cx);   // 连续拖动 → Command::merge 合并为一步撤销(分册三 §2,已实现)
    }
    // 修饰键惯例:↑↓ 步进、Shift+↑↓ 大步进、Enter 提交、Esc 取消 —— 复用 gpui-component Input 的键位
}
```

> 上游语义对齐(VellumBench 的 scrubby 实证结论,**只对齐行为规格**):
> - 表达式求值(`1+2`、`2*3cm`)做进纯函数模块(零 egui/gpui 依赖,可独立测试)—— VB 的 `expr.rs` 证明了这条路;
> - 控件高度按分册六 §3 的派生制(三档为下限),CJK 行高不压字;
> - tabular-nums 等宽字体显示数值,拖动时数值不跳动。

## 8. 时间轴 Timeline(剪映核心,M4 主战场)

**信息架构**:

```
┌────────────────────────────────────────────────┐
│ 工具行:撤销/分割/删除/吸附/缩放滑杆                 │
├──┬─────────────────────────────────────────────┤
│轨│  时间标尺(帧/秒自适应刻度)                     │
│道│  ├─ 播放头(红线,可拖)                        │
│头│  ├─ 视频轨2: [clip]      [clip]               │
│区│  ├─ 视频轨1: [clip][clip]   [clip]            │
│  │  ├─ 贴纸轨:  [sticker]                       │
│  │  ├─ 音频轨:  [▁▃▅▂波形▃▁]                     │
│  │  └─ 字幕轨:  [字幕][字幕]                      │
└──┴─────────────────────────────────────────────┘
```

**数据模型**(与 UI 解耦,可撤销/可序列化;**✅ 已实现于 `crates/sable-video/src/model.rs`**,节选):

```rust
// sable-video(已实现)
/// clip 的稳定身份:自增 u64,**永不复用**(连跳号都不回收)。
/// 由 Timeline 内部铸造(外部不可构造);发号器 serde 持久化,重开工程不复用 id。
pub struct ClipId(u64);

pub enum TrackKind { Video, Audio, Sticker, Subtitle }

pub struct Clip {
    pub id: ClipId,
    pub asset: AssetRef,           // 素材引用(路径 + 内容哈希;v0.1 存路径+哈希,解码 v0.2 进程隔离)
    pub start_ms: u64,             // 时间轴域起点
    pub duration_ms: u64,          // 变速时 = round((out_ms - in_ms) / speed)
    pub in_ms: u64, pub out_ms: u64,   // 素材内出入点(源域)
    pub speed: f64,                // > 0
    pub keyframes: Vec<Keyframe>,  // §9 曲线编辑器的数据(t_ms 为 clip 本地时间)
}

pub struct Track {
    pub kind: TrackKind,
    pub clips: Vec<Clip>,          // 不变量:按 start_ms 严格升序、互不重叠(相邻贴合允许)
    pub muted: bool, pub locked: bool,
}

pub struct Timeline {
    pub tracks: Vec<Track>,
    pub px_per_second: f64,        // 时间轴缩放(ms_to_px / px_to_ms 换算)
    pub snap_enabled: bool,
    pub duration_ms: u64,          // 派生缓存:全轨 max(clip end)
    // next_clip_id 私有发号器(serde 持久化;手写 PartialEq 刻意排除它 —— id 只进不退,
    // 撤销等价性必须无视计数器,与 Scene 的结构化相等同一思想)
}
// 模型层修改 API(不变量内部维护,is_valid() 可随时校验):
//   place_clip / move_clip / trim_clip / split_at / remove_clip / ripple_remove
//   / set_speed / snap(就近吸附,容差过滤)/ snap_targets(播放头、clip 边缘、标记点候选)
// 独立纯函数:snap_time(raw, tolerance, targets)(等距并列取先出现者)
```

> ### ⭐ 2026-10 落地决策:TimelineCommand 独立同构 + sable-video 依赖解耦
>
> 1. **`TimelineCommand` 独立于场景图命令**:时间轴修改(MoveClip/SplitClip/TrimClip…)将走一套**独立同构**的命令枚举(trait 形状与分册三 §2 相同:apply/revert/merge),但 **`ClipId` 是稳定自增 u64、永不复用**(model.rs 已按此铸造:发号器 serde 持久化、`PartialEq` 刻意排除计数器)—— 失效引用只会"目标已删除",绝不会误指新 clip,**不需要 IdRemap 治愈机制**(model.rs 模块注释原话:这是本 crate 撤销机制远比 sable-foundation 简单的根本原因)。命令层 `TimelineCommand` 本体为规划(模型层修改 API 已就绪,命令层是其薄包装)。
> 2. **sable-video 不依赖 sable-canvas**(偏离分册六 §2.1 金字塔的原画法):`crates/sable-video/Cargo.toml` 只依赖 sable-foundation + kurbo/serde/thiserror/tracing。理由:时间轴模型不需要场景图;时间轴*视图*才在 sable-widgets 中。依赖图变为 `video → core` 与 `widgets → canvas → paint → core` 并行,编译更快、裁剪更细(只用时间轴的宿主不必拉画布)。分册六 §8 修正表已登记此偏差。
> 3. **领域参照**:CutForge 的 `cutforge-core` 已工程化验证了同构模型(Track/Clip 785 行 model、18 变体 Command、trim/roll/slip/slide 四模式、OpLog 回放 12000 组属性测试)。**ARL-1.0 红线:零源码复制**,只按其 README/schema 契约对齐语义,见 [upstream/01-cutforge-ui-analysis.md](upstream/01-cutforge-ui-analysis.md) §3.1/§3.2 与 NOTICE.md。

**核心交互实现要点**:

```rust
impl TimelineView {
    /// 拖动 clip:像素 ↔ 毫秒换算 + 吸附
    fn on_clip_drag(&mut self, clip: ClipId, dx_px: f32, cx: &mut Context<Self>) {
        let state = self.timeline.read(cx);
        let d_ms = (dx_px as f64 / state.px_per_second * 1000.0) as i64;
        let raw = (self.drag_origin_ms as i64 + d_ms).max(0) as u64;
        let snapped = if state.snap_enabled {
            self.snap_targets(raw)   // 候选:播放头、其他 clip 边缘、标记点
                .min_by_key(|t| t.abs_diff(raw))
                .filter(|t| t.abs_diff(raw) < 8.0 / state.px_per_second * 1000.0)
                .unwrap_or(raw)
        } else { raw };
        self.doc.update(cx, |d, cx| {
            d.exec_timeline(TimelineCommand::MoveClip { clip, to: snapped }, cx)
        });
    }

    /// 波形图:symphonia 解码后按分钟聚合 min/max 柱,缓存进纹理
    fn waveform_texture(&self, clip: &Clip) -> TextureId { /* 采样 ~200 柱/秒,clip 级缓存 */ }
}
```

> **性能红线**:拖动 clip 时**不重解码**。预览监视器按 `playhead_ms` 从解码缓存取最近帧;只有播放头跳转才 seek。参考 Gausian 的 WGPU 预览管线与 CutForge 的 render_frame 缓存键设计(工作区指纹 + atMs 100ms 量化 + 画幅 + 渲染版本,见 [upstream/01-cutforge-ui-analysis.md](upstream/01-cutforge-ui-analysis.md) §3.3)。
> **吸附语义归属(上游教训)**:吸附/重叠/时长推导的"真相"必须在模型层(sable-video),视图只做投影 —— CutForge 用 check-shell-purity 门禁看住 Web 壳不持真相,桌面壳同理,见 [upstream/00-总结与迁移路线.md](upstream/00-总结与迁移路线.md) §4.3。

## 9. 曲线编辑器 CurveEditor(速度曲线/关键帧缓动)

剪映的"曲线变速"= 时间重映射曲线,缓动 = 关键帧插值曲线。两者同一个组件:

```rust
pub struct CurveEditor {
    binding: Binding<Vec<CurveKey>>,   // 每个 key: (t, v, in_handle, out_handle)
    range_t: (f64, f64), range_v: (f64, f64),
    selected: Option<usize>,
    preset: Option<EasingPreset>,      // 内置:线性/缓入/缓出/弹簧…
}
// 绘制:keys 连成 kurbo::BezPath(手柄即贝塞尔控制点)→ PaintSink stroke(覆盖层线宽)
// 求值:kurbo 的曲线求值(给定 t 二分求 x 轴交点)→ 播放器每帧调用
// 交互:拖 key 改值、拖手柄改曲率、双击线加 key、右键删 key
```

> **数据面已实现**:单值 `Keyframe { t_ms(clip 本地时间), value, easing }` 与预设 `Easing`(Linear/InCubic/OutCubic/InOutCubic/Spring)已落盘于 `sable-video/src/model.rs`;移动 clip 关键帧随动、分割 clip 按本地分割点切分的语义在模型层维护。组件本体与求值引擎规划 M4(可降级预设缓动)。
> CutForge 侧对应物是 `SpeedPoint` 曲线与 `keyframes.rs`(782 行独立模块)—— 语义可对齐,源码不可碰(ARL-1.0)。砍范围降级预案:曲线编辑器可先降级为预设缓动(分册五 §4)。
