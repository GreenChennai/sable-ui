# 00 · 上游接入总结与迁移路线(CutForge × VellumBench → Lumina)

> 分析基线:2026-10-02。分册:[01-cutforge-ui-analysis.md](01-cutforge-ui-analysis.md) · [02-vellumbench-ui-analysis.md](02-vellumbench-ui-analysis.md)。
> 注:Lumina 仓库当前只有 README/AGENTS/NOTICE 三份根文档,docs/00–06 与 docs/05 的 M0–M5 里程碑**尚未落盘**(README.md:5、AGENTS.md §5 引用之)。本文按 README 的 crate 金字塔给出里程碑**建议映射**,待 docs/05 正式版出来后以其为准。

## 1. 三方角色一句话

| 项目 | 对 Lumina 的角色 | 一句话 |
|---|---|---|
| **CutForge** | **第一个宿主应用**(消费者)+ 时间轴领域模型参照 | 内核与 Web 壳已成品,桌面壳(apps/desktop)因 GPUI 不成熟被降级为观察项——Lumina 成熟之日就是它复活之时(apps/desktop/README.md:3-12) |
| **VellumBench** | **设计语义供体**(donor),现阶段不接入运行时 | vb_ui 的令牌值/组件规格/工程纪律对齐进 lumina-widgets;ACL-1.0 禁止任何源码复制(NOTICE.md 已登记纪律) |
| **Lumina** | 统一前端库 | GPUI 管窗口与面板,Vello 管画布(README.md:9) |

## 2. 谁先用哪个 crate

```
CutForge apps/desktop(未来)                VellumBench(只读语义,不依赖)
 ├─ lumina-dock      ← Dock 工作台/面板/命令面板/布局序列化
 ├─ lumina-video     ← 时间轴数据模型的领域参照(轨道/clip/关键帧/吸附/播放时钟)
 ├─ lumina-widgets   ← 时间轴视图/NumberField/ColorField/Toast/检查器骨架
 │                      (令牌与组件规格语义来自 vb_ui 对齐)
 ├─ lumina-canvas    ← 预览画布/视口/命中测试
 └─ lumina-paint     ← Vello 原语(示波器/波形/渐变条自绘)
        ↑ 经 /rpc + SSE 或进程内 Command 通道            (无运行时依赖)
        ↓ 数据/命令
   cutforge 内核(core/io/render/mcp)—— 语义与真相永远在内核
```

- **CutForge 消费面**:lumina-dock(必须先于一切)、lumina-video(桌面壳核心)、lumina-widgets(检查器/时间轴)、lumina-canvas+paint(预览与数据可视化)。它**不需要** Lumina 提供撤销栈做文档语义——那由 cutforge Engine 承担;lumina-core 的 Command/History 只管 UI 层命令(视图态、面板开关)与键位绑定。
- **VellumBench 消费面**:零运行时依赖;只把 §3 的语义层迁进 lumina-widgets/lumina-dock 的**规格与测试**。VellumBench 自身未来若迁移 GPUI,是另一个独立工程(其 vb_app 有 63 个文件用 egui,主工程量在面板层,见 02 分册 §5)。

## 3. 里程碑映射(建议;对照 docs/05 落盘后校正)

| Lumina 建议里程碑 | 交付物 | CutForge 侧对应动作 | VellumBench 侧对应动作 |
|---|---|---|---|
| **M0 基础层** | lumina-core(视口/Command/History/token 基础)+ lumina-paint(vello 后端/GpuGuard) | 无(等待) | expr 求值器语义、tokens 事实表定稿(02 分册 §3) |
| **M1 画布层** | lumina-canvas(场景图/命中/LOD) | 无 | 光标映射表、语义色(参考线/选中框)进入 token |
| **M2 组件层** | lumina-widgets:tokens.rs(+tokens_sync CI)/NumberField/ColorField/Toast/主题注入/动画引擎 | 无(组件验收场还没到) | **令牌与组件行为规格全面对齐**(02 分册 §4/§6 步骤 1–4);控件高度体系裁决(22/26/32 vs 派生制) |
| **M3 面板层** | lumina-dock:DockArea 封装/面板 Tab/窄窗折叠规则/布局序列化/命令面板/keymap | apps/desktop P0 骨架:三栏布局 + `/rpc` 只读投影 + 时间轴只读渲染(= 恢复门禁的"开窗+加载工程+渲染时间线"冒烟) | dock 折叠规则表/PanelTabs 换序协议写入 lumina-dock 规格 |
| **M4 时间轴层** | lumina-video:轨道/clip/关键帧/吸附/播放时钟 + lumina-widgets 时间轴视图 | apps/desktop P1–P2:拖拽/trim→命令提交、SSE 回流、ui-fields 驱动检查器、catalogs 驱动库面板 | 无 |
| **M5 应用层** | examples/video_editor 完善;apps/desktop 落地路径成熟 | P3–P5:render_frame 预览、波形/示波器绘制、历史/差异面板、(可选)进程内化;满足 ADR-0039 恢复条件后桌面壳转正 | (远期)VellumBench 自身迁移另立评估 |

**关键判断:CutForge 是 Lumina 的第一个真实验收场,lumina-dock + lumina-video 是它的最小可用集;VellumBench 的语义对齐必须赶在 lumina-widgets tokens.rs/组件定稿(M2)之前完成,否则返工。**

## 4. 总风险清单(按严重度)

1. **双许可雷区(阻断级)**:
   - CutForge 原创部分 **ARL-1.0**,`CORE-FILES` 36 个核心文件修改须回传开源(CORE-FILES;README.md:185-193)。Lumina 库侧必须零复制,只消费 JSON 契约(schema/ui-fields/catalogs)与 RPC 面;apps/desktop 作为"壳"属可闭源侧,但应独立于 lumina-* crate。
   - VellumBench **ACL-1.0** 传染条款:再分发实质部分必须整体 ACL-1.0 开源,网络服务也算(LICENSE 四.1–四.4)。**只许语义/设计思想对齐,禁止复制源码,禁止逐行翻译**(实现者以规格文档为输入,不对照 .rs 写码,详见 02 分册 §0/§7)。
2. **GPUI 生态成熟度(战略级)**:CutForge 桌面壳正是因为"GPUI 0.2.2 生态尚在演进"而降级(apps/desktop/README.md:5-8)。Lumina 与 cutforge 桌面壳共担同一赌注;CutForge 定的复活条件(GPUI 稳定版 + Windows 冒烟)应直接抄为 Lumina M3 的验收门槛。
3. **壳语义漂移(架构级)**:CutForge 用 check-shell-purity 门禁看住 Web 壳"不持真相、不算时间线语义"(cutforge-wasm/lib.rs:5-8;README.md:107)。桌面壳是第二个壳,任何在 Lumina 侧手写的吸附/重叠/时长推导都会制造第二真相——lumina-video 与 cutforge-core 的模型边界(谁存真相、谁只做视图投影)必须在 apps/desktop 动工前写进 ADR。
4. **控件/令牌体系未裁决(返工级)**:VB 行高派生制(下限 24)vs Lumina AGENTS 固定档(22/26/32);egui 特有修补经验不可平移,GPUI 需要自己的观感走查(02 分册 §7.2/7.3)。M2 前不裁决,lumina-widgets 必返工。
5. **预览能力差距(体验级)**:render_frame 单帧 100ms 量化(cutforge-render/src/frame.rs:15)只够"精确预览";连续播放预览桌面端与 Web 壳同受限(段级代理预览)。若产品预期是"剪映级实时预览",需要 M6 渲染后端阶段的解码帧流方案,Lumina 侧预留 GPUI 纹理上传通道(lumina-canvas)即可,不要提前建视频解码层。
6. **文档/UI 令牌命名空间(数据级)**:两个上游都有"软件外观色"与"用户内容色"两套域(VB 的 --vb-ui-* vs --vb-brand-*;CutForge 的界面主题 vs 字幕/转场颜色)。lumina tokens.rs 从第一天就要分离,否则库层 token 会污染用户工程数据(02 分册 §7.4)。
7. **键位与命令双表(集成级)**:CutForge 45 条可重绑定快捷键注册表与 gpui-component keymap 是两套表;建议命令 ID 以 cutforge 注册表为单源,Lumina keymap 只做绑定层(01 分册 §7.5)。

## 5. 立即可做的三件事

1. 把本文 §4.1 的两条许可纪律写进 Lumina AGENTS.md §4 的移植规则(ARL-1.0 条目目前缺位,NOTICE.md 只有 ACL-1.0 条)。
2. 在 docs/05 落盘时采纳 §3 的里程碑→上游动作映射,并给 lumina-dock 定"开窗+加载工程+渲染时间线"三步冒烟为 M3 验收。
3. 按 02 分册 §6 步骤 1 启动 tokens 事实表定稿(色值/间距/圆角/动效四表直接取自 vb-ui-tokens.json 的客观数值),同步裁决控件高度体系。
