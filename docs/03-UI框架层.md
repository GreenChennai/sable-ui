## 1. GPUI 编程模型精讲(Lumina 的地基)

GPUI 的三件套,必须先吃透:

```
Entity<T>     = 一块状态的句柄(所有权归 App 上下文,你拿的是引用)
Context<T>    = 访问/修改状态的入口,同时也是事件总线
Render trait  = 状态 → UI 树的纯函数(每帧/每次 notify 调用)
```

```rust
// 1. 定义状态实体
struct Document {
    scene: Scene,              // lumina-core(分册二 §3,已实现)
    selection: Vec<NodeId>,
    history: History,          // 撤销栈,见 §2(已实现)
}

// 2. 在 App 启动时注册
let doc = cx.new(|_| Document::new());

// 3. 视图中读取(只读借用)
let title = doc.read(cx).scene.len();

// 4. 视图中修改(可变借用 + 通知)
doc.update(cx, |doc, cx| {
    doc.history.exec(RemoveNode::new(id).boxed(), &mut doc.scene);
    cx.notify();               // 订阅者重绘
});

// 5. 跨实体通信:订阅
cx.subscribe(&doc, |view, _doc, event: &DocEvent, cx| {
    match event { DocEvent::SelectionChanged => view.sync_inspector(cx), }
}).detach();
```

**设计软件的实体划分建议**(单一职责,避免上帝对象):

| Entity | 职责 |
|---|---|
| `Document` | 场景图、选中集、历史栈(撤销重做) |
| `ToolState` | 当前工具、工具临时状态(钢笔路径草稿) |
| `ViewportState` | 每个画布的 zoom/pan(多画布时每个一份;数据类型 `lumina_core::Viewport` 已实现) |
| `AppSettings` | 主题、语言、快捷键映射、最近文件 |
| `ClipboardState` | 内部剪贴板(跨文档复制粘贴) |
| `TimelineState` | (剪映模块)播放头、轨道、播放状态 |

## 2. 命令系统:撤销重做的唯一正解

**设计软件的铁律:一切文档修改必须走 Command,没有例外。** 直接改 `scene` 的地方不允许存在。

> ### ⭐ 2026-10 落地决策:trait 签名升级 + IdRemap 治愈(已实现,`crates/lumina-core/src/command.rs`)
>
> 本节是 v0.1 相对原文**改动最大**的一章,动机只有一个 —— **slotmap 的 key 无法复原**:
> - 已核实 slotmap 1.1.1 源码:`KeyData` 字段私有,slot 版本号单调递增,**不存在 `insert_with_id` 之类的安全 API**;
> - 因此"删除节点 → 撤销"必然**换发新 id**(`Scene::undo_remove` 返回 `IdRemap`,见分册二 §3);
> - 若历史栈里的旧命令仍引用旧 id,"改子节点属性 → 删父组 → 撤销×2"这类基础流程会**静默失效**。
>
> 治愈机制三件套(全部有测试背书):
> 1. `apply`/`revert` 接收 **`&mut self`**:`AddNode`/`RemoveNode` 要在 undo/redo 任意次循环中追踪"当前生效 id";
> 2. `revert` 返回 **`Option<IdRemap>`**:恢复子树的命令(old→new 映射)上报;
> 3. `History` 在每次 undo 后把映射**广播给全部历史条目**(`Command::remap_ids`)—— 专门测试 `undo_after_remove_heals_ids_of_older_entries` 验证该场景。
>
> **视频时间轴不进这套重映射**:lumina-video 用独立同构的 `TimelineCommand`(见分册四 §8),`ClipId` 是稳定 u64,没有 slotmap 版本号问题 —— 时间轴命令不需要治愈机制,这是两套命令系统分开而非复用的理由。

```rust
// lumina-core/src/command.rs(已实现,签名照抄源码)
use crate::scene::{IdRemap, NodeId, Scene};

/// 命令 = 一次可逆的文档修改。
/// 注意:Command 不要求 Clone(revert 会更新自身缓存的 id,克隆语义易错)。
pub trait Command: Send + 'static {
    /// 正向执行(&mut self:结构型命令要追踪当前生效 id)
    fn apply(&mut self, scene: &mut Scene);

    /// 逆向执行(撤销)。恢复子树的命令返回 old→new 重映射表,其余返回 None。
    fn revert(&mut self, scene: &mut Scene) -> Option<IdRemap> { None }

    /// 命令合并(连续输入/拖动 → 合并为一步撤销;保留最早的 old、最新的 new)
    fn merge(&self, next: &dyn Command) -> Option<Box<dyn Command>> { None }

    /// merge 里 downcast 用,必填。
    fn as_any(&self) -> &dyn Any;

    /// 结构型命令实现:按映射重写自身缓存的节点 id(History 在 undo 后统一调用)。
    fn remap_ids(&mut self, map: &IdRemap) { /* 默认空 */ }

    /// 命令名(历史面板/日志用;Cow 免持有者分配字符串)。
    fn name(&self) -> Cow<'static, str>;

    /// 装箱为 trait object。
    fn boxed(self) -> Box<dyn Command> where Self: Sized { Box::new(self) }
}

/// 历史栈:撤销/重做的唯一入口(已实现)。
pub struct History {
    undo: Vec<Box<dyn Command>>,
    redo: Vec<Box<dyn Command>>,
    /// 批量事务:如"对齐 5 个对象" = 一步撤销
    transaction: Option<Vec<Box<dyn Command>>>,
}

impl History {
    pub fn exec(&mut self, mut cmd: Box<dyn Command>, scene: &mut Scene) {
        cmd.apply(scene);
        match &mut self.transaction {
            Some(batch) => batch.push(cmd),
            None => {
                // 尝试与栈顶合并(连续打字/拖动场景)
                let merged = self.undo.last().and_then(|top| top.merge(&*cmd));
                if let Some(merged) = merged {
                    self.undo.pop(); self.undo.push(merged);
                } else {
                    self.undo.push(cmd);
                }
                self.redo.clear();
            }
        }
    }

    /// 撤销一步;子树恢复产生的 id 重映射会广播给全部历史条目(治愈的关键)。
    pub fn undo(&mut self, scene: &mut Scene) {
        if let Some(mut cmd) = self.undo.pop() {
            let remap = cmd.revert(scene);
            self.redo.push(cmd);
            if let Some(map) = remap {
                self.remap_all(&map);   // undo + redo + 事务中 全部修正
            }
        }
    }

    /// 重做一步(按撤销的逆序逐条重放)。
    pub fn redo(&mut self, scene: &mut Scene) { /* ... */ }

    pub fn begin_transaction(&mut self) { /* 嵌套调用被忽略,不丢已收集命令 */ }
    pub fn end_transaction(&mut self) { /* 空事务不产生撤销步 */ }

    pub fn can_undo(&self) -> bool { /* ... */ }
    pub fn can_redo(&self) -> bool { /* ... */ }
    /// 撤销栈深度(自动保存用:每 N 个未存命令触发一次,分册六 §1.2)
    pub fn undo_len(&self) -> usize { /* ... */ }
    pub fn clear(&mut self) { /* "打开新文档"时清空全部历史 */ }
}
```

v0.1 **内置命令集**(全部实现于 `command.rs`,经 prelude re-export):

| 命令 | 语义 | merge | 备注 |
|---|---|---|---|
| `AddNode` | 定点插入节点模板 | — | `id: Option<NodeId>` 追踪 slotmap 实发号;undo = 摘除 |
| `RemoveNode` | 删除节点及子树 | — | `RemovedSubtree` 全保存;undo 返回 `IdRemap` 并自愈 `self.id` |
| `SetTransform` | 修改局部变换 | — | — |
| `SetFill` | 修改路径填充 | ✅ 同节点合并 | 保留最早的 old、最新的 new |
| `SetStroke` | 修改路径描边 | ✅ 同节点 | 同 `SetFill` |
| `SetOpacity` | 修改不透明度 | ✅ 同节点 | apply/revert 双侧 clamp 到 [0,1] |
| `SetVisibility` | 修改可见性 | — | 图层面板眼睛图标用 |
| `SetName` | 重命名 | — | — |
| `Reparent` | 移动到新父节点 | — | `Reparent::capture` 从场景读当前(父,下标)做回退锚点 |
| `BatchCommand` | 事务批量 | — | revert 逆序回退,且**某步产生重映射时先喂给尚未回退的前序命令**,累积映射做"值穿过映射"合成 |

典型命令实现(属性修改,演示合并,已实现):

```rust
pub struct SetFill {
    pub id: NodeId,
    pub new: Option<Paint>,
    pub old: Option<Paint>,     // 执行前捕获,供 revert
}

impl Command for SetFill {
    fn apply(&mut self, scene: &mut Scene) {
        if let Some(p) = scene.path_mut(self.id) { p.fill = self.new.clone(); }
    }
    fn revert(&mut self, scene: &mut Scene) -> Option<IdRemap> {
        if let Some(p) = scene.path_mut(self.id) { p.fill = self.old.clone(); }
        None
    }
    fn merge(&self, next: &dyn Command) -> Option<Box<dyn Command>> {
        // 色轮上连续拖 → 合并为一次撤销(保留最早的 old、最新的 new)
        let next = next.as_any().downcast_ref::<SetFill>()?;
        if next.id != self.id { return None; }
        Some(Box::new(SetFill { id: self.id, new: next.new.clone(), old: self.old.clone() }))
    }
    fn remap_ids(&mut self, map: &IdRemap) {
        self.id = map.get(&self.id).copied().unwrap_or(self.id);
    }
    fn as_any(&self) -> &dyn Any { self }
    fn name(&self) -> Cow<'static, str> { Cow::Borrowed("修改填充") }
}
```

## 3. 组件模型:Lumina 组件三件套约定

gpui-component 的组件是**无状态 `RenderOnce`**(构建即渲染),Lumina 沿用这一约定,并补充两类:

| 类型 | GPUI 机制 | 适用 | 例子 |
|---|---|---|---|
| **无状态组件** | `impl RenderOnce` | 外观件,父级传值 | Button、ColorWell、SliderRow |
| **有状态视图** | `impl Render` + Entity | 自持状态的复杂件 | LayerPanel、Timeline、ColorWheel |
| **受控组件** | `RenderOnce` + 外部 Entity | 状态在文档里的件 | PropertyField(改文档属性) |

```rust
// 约定示例:受控属性行 —— 所有"属性检查器"里的行都长这样(规划,lumina-widgets)
pub struct PropertyRow {
    label: SharedString,
    control: AnyElement,
}
impl RenderOnce for PropertyRow {
    fn render(self, _: &mut Window, _: &mut App) -> impl IntoElement {
        h_flex()
            .gap_2().items_center()
            // 控件高度走 tokens(分册六 §3):三档 22/26/32 是"下限",
            // 实际高度 = max(档位, 文本行高 + 2×垂直 padding)—— 压 CJK 教训
            .h(tokens.control_height_default())
            .child(div().w(px(72.)).text_sm().text_color(tokens.text_secondary).child(self.label))
            .child(div().flex_1().child(self.control))
    }
}

// 用法(属性检查器里):
PropertyRow::new("X").control(NumberField::new(cx, pos_x_binding))
PropertyRow::new("填充").control(ColorWell::new(cx, fill_binding))
```

## 6. 面板布局(Dock 系统)

直接用 gpui-component 的 DockArea(可拖拽/嵌套/序列化布局),定义 Lumina 的"工作台"。**依赖已接好**:`crates/lumina-dock/Cargo.toml` 已含 `gpui 0.2.2` + `gpui-component 0.7.0`(crates.io):

```rust
use gpui_component::dock::{DockArea, DockItem, Panel, PanelView};

pub fn build_workspace(window: &mut Window, cx: &mut App) -> Entity<DockArea> {
    cx.new(|cx| {
        let mut area = DockArea::new("workspace", Some(1), window, cx);

        let canvas = DockItem::panel(Arc::new(CanvasPanel::new(cx)), &area, window, cx);
        let layers = DockItem::panel(Arc::new(LayerPanel::new(cx)), &area, window, cx);
        let inspector = DockItem::panel(Arc::new(InspectorPanel::new(cx)), &area, window, cx);
        let assets = DockItem::panel(Arc::new(AssetPanel::new(cx)), &area, window, cx);

        // 经典三段式:左(图层+素材) | 中(画布) | 右(属性)
        area.set_left_dock(vec![layers, assets], Some(px(260.)), true, window, cx);
        area.set_right_dock(vec![inspector], Some(px(300.)), true, window, cx);
        area.set_center(canvas, window, cx);
        area
    })
}

// 每个面板实现 gpui-component 的 Panel trait → 自动获得 Tab/拖拽/关闭行为
impl Panel for LayerPanel {
    fn panel_name(&self) -> &'static str { "图层" }
    fn title(&self, _: &App) -> AnyElement { "图层".into_any_element() }
}
```

布局可序列化(`DockArea::dump` / `load`)→ 用户自定义工作区存进偏好设置,重启恢复 —— Illustrator 的"工作区"功能零成本获得。

## 7. 剪映模块的 UI 差异点

视频软件的框架层有两处特殊设计,提前在核心层预留:

1. **播放时钟**:`cx.background_executor().timer()` 驱动播放头,UI 只订阅"时间码变化",不持有解码线程
2. **帧节流**:解码线程产帧 → `smol::channel`(容量 2,丢旧帧保新帧)→ UI 取最新帧转 wgpu 纹理

```rust
// lumina-video 的播放泵(骨架;播放时钟已列入 lumina-video 规划面)
struct Player { position_ms: u64, playing: bool, speed: f64 }
impl Player {
    fn start_pump(&mut self, cx: &mut Context<Self>) {
        cx.spawn(|this: WeakEntity<Player>, cx: &mut AsyncApp| async move {
            let mut last = std::time::Instant::now();
            loop {
                smol::Timer::after(std::time::Duration::from_millis(16)).await;
                let _ = this.update(cx, |p, cx| {
                    if p.playing {
                        p.position_ms += (last.elapsed().as_secs_f64() * 1000. * p.speed) as u64;
                        cx.notify();   // 时间轴/预览订阅此通知
                    }
                });
                last = std::time::Instant::now();
            }
        }).detach();
    }
}
```

> **命令系统分层(2026-10 落地决策)**:时间轴的一切修改走**独立同构的 `TimelineCommand`**(`ClipId` 稳定 u64,无重映射问题),不复用场景图的 `IdRemap` 治愈机制 —— 两套数据模型的 id 语义不同,强行复用会把治愈复杂度传染给不需要它的模型。详见分册四 §8。
