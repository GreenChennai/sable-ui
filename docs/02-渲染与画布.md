## 2. 核心概念:两套坐标系

设计软件的一切交互都要在这两套坐标系之间换算,这是画布内核的第一性原理:

```
屏幕坐标 (screen px)  ←─→  世界坐标 (document units)
        viewport_to_world()      world_to_viewport()
```

以下代码**已按 kurbo 0.13 实际签名落地**于 `crates/sable-foundation/src/viewport.rs`(与原文差异:`Affine::translate` 直接吃 `Into<Vec2>`,并补 `PartialEq` 与单元测试):

```rust
// sable-foundation/src/viewport.rs(已实现)
use kurbo::{Affine, Point, Vec2};

/// 视口:管理世界坐标 ↔ 屏幕坐标的全部换算
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Viewport {
    /// 缩放因子,1.0 = 100%
    pub zoom: f64,
    /// 世界原点在屏幕上的偏移(平移量)
    pub pan: Vec2,
}

impl Viewport {
    pub const MIN_ZOOM: f64 = 0.01;   // 1%
    pub const MAX_ZOOM: f64 = 64.0;   // 6400%

    /// 世界 → 屏幕:先缩放,再平移
    pub fn world_to_viewport(&self) -> Affine {
        Affine::translate(self.pan) * Affine::scale(self.zoom)
    }

    /// 屏幕 → 世界(逆变换,Affine 可逆是 kurbo 的免费午餐)
    pub fn viewport_to_world(&self) -> Affine {
        self.world_to_viewport().inverse()
    }

    pub fn screen_to_world(&self, screen: Point) -> Point {
        self.viewport_to_world() * screen
    }

    pub fn world_to_screen(&self, world: Point) -> Point {
        self.world_to_viewport() * world
    }

    /// 以光标为锚点缩放(滚轮缩放的关键体验:光标下的点不动)
    pub fn zoom_at(&mut self, screen_anchor: Point, factor: f64) {
        let world_anchor = self.screen_to_world(screen_anchor);
        self.zoom = (self.zoom * factor).clamp(Self::MIN_ZOOM, Self::MAX_ZOOM);
        // 重新计算 pan,使 world_anchor 仍落在 screen_anchor 上
        let new_screen = self.world_to_screen(world_anchor);
        self.pan += screen_anchor - new_screen;
    }

    pub fn pan_by(&mut self, delta_screen: Vec2) {
        self.pan += delta_screen;
    }
}
```

> **工程要点**:永远不要存"屏幕坐标"进文档模型。文档模型(形状、锚点)一律世界坐标;屏幕坐标只在事件处理和绘制瞬间存在。
>
> 已落地的验收测试(`viewport.rs` `#[cfg(test)]`):锚点不漂移(`zoom_at_anchor_does_not_drift`)、screen↔world 往返恒等、仿射矩阵与逐点换算一致、clamp 边界、平移语义 —— 对应 §9 验收清单第一条。

## 3. 场景图:文档的内存表示

> ### ⭐ 2026-10 落地决策:Scene 从 sable-canvas 下沉进 sable-foundation
>
> 原方案把场景图放在 sable-canvas;v0.1 实现把它**下沉到 `crates/sable-foundation/src/scene.rs`**。原因:
> 1. **Command/History 必须能命名被编辑的状态**(AGENTS.md §3.1:一切文档修改走 Command)—— 命令系统在 core,它引用的 `NodeId`/`Scene` 也必须在 core,否则出现 core→canvas 的反向依赖;
> 2. Scene 是**纯数据**:kurbo / slotmap(serde)/ serde / thiserror 恰好全部在 core 的零 UI 依赖白名单内,下沉零成本;
> 3. canvas crate 保留**行为层**(hit_test / grid / damage / lod / tool / render)。
>
> 由此 core 白名单有一处修正:原文写的 `kurbo/peniko/serde/slotmap` 中,**peniko 已移除** —— 场景图改用自有 `Paint` 枚举(见下),序列化友好且不让 core 背 peniko 的 serde 面;peniko 转换留在 sable-paint(`style.rs` 的 `to_brush`)。

Illustrator 的"图层"本质是**一棵树**,用 `slotmap` 管理句柄(避免悬垂引用,比 `Rc<RefCell>` 工程上健康得多):

```rust
// sable-foundation/src/scene.rs(已实现,节选;完整签名以源码为准)
use kurbo::{Affine, BezPath, Rect};
use serde::{Deserialize, Serialize};
use slotmap::{SlotMap, new_key_type};

new_key_type! {
    /// 场景节点句柄(slotmap key,值语义;序列化后可跨进程往返)。
    pub struct NodeId;
}

/// 0-255 RGBA 颜色。v0.1 用字节组而非 peniko::Color:零依赖、serde 直出。
pub type Rgba8 = [u8; 4];

/// 节点 id 重映射:摘除子树被恢复时,旧 id → 恢复后新 id(见 undo_remove)。
pub type IdRemap = HashMap<NodeId, NodeId>;

/// 填充/描边用的绘制源(自有枚举,不引 peniko:Solid / 线性 / 径向渐变)。
#[derive(Clone, Debug, PartialEq, Serialize, Deserialize)]
pub enum Paint {
    Solid(Rgba8),
    LinearGradient { start: [f64; 2], end: [f64; 2], stops: Vec<GradientStop> },
    RadialGradient  { center: [f64; 2], radius: f64, stops: Vec<GradientStop> },
}

/// 描边样式(颜色 + 线宽;线型/端帽 v0.1 不做)。
#[derive(Clone, Debug, PartialEq, Serialize, Deserialize)]
pub struct StrokeStyle { pub paint: Paint, pub width: f64 }

pub struct PathNode  { pub path: BezPath, pub fill: Option<Paint>, pub stroke: Option<StrokeStyle> }
pub struct TextNode  { pub text: String, pub font_size: f64, pub color: Rgba8 }   // 布局缓存归 canvas 文本管线
pub struct ImageNode { pub rect: Rect, pub name: String }                          // v0.1 占位:像素走资产管线

/// 节点内容:设计软件里"一个对象"的种类。
pub enum NodeContent { Group, Path(PathNode), Text(TextNode), Image(ImageNode) }

/// 场景节点。
pub struct Node {
    pub name: String,
    pub parent: Option<NodeId>,
    pub children: Vec<NodeId>,
    pub transform: Affine,       // 相对父节点的局部变换
    pub visible: bool,
    pub locked: bool,
    pub opacity: f64,            // 渲染时与父链累乘
    pub content: NodeContent,
}

/// 场景:slotmap 句柄表 + 根节点渲染序(渲染顺序 = 数组顺序,底→顶)。
/// PartialEq 是"结构化相等":从 roots 递归比较节点数据,不比较 slotmap key 版本号。
#[derive(Clone, Debug, Default, Serialize, Deserialize)]
pub struct Scene {
    pub nodes: SlotMap<NodeId, Node>,
    pub roots: Vec<NodeId>,                 // 顶层图层(渲染顺序 = 数组顺序)
}

impl Scene {
    /// 深度优先遍历,产出"世界变换已应用"的渲染列表(不可见节点整棵剪枝)
    pub fn render_list(&self) -> Vec<(NodeId, Affine)> { /* walk,底→顶 */ }
    /// 世界变换:沿 parent 链从根到本节点累乘(parent 链成环防御:步数上界=节点总数)
    pub fn world_transform(&self, id: NodeId) -> Option<Affine> { /* ... */ }
    /// 内容包围盒 × 世界变换;Group = 子节点世界包围盒并集;Text 粗估不引 parley
    pub fn node_world_bbox(&self, id: NodeId) -> Option<Rect> { /* ... */ }
    /// 追加 / 定点插入 / 摘除整棵子树 / 恢复(带 id 重映射) / 移动(成环检测)
    pub fn add_node(&mut self, parent: Option<NodeId>, name: impl Into<String>,
                    content: NodeContent) -> CoreResult<NodeId>;
    pub fn insert_at(&mut self, parent: Option<NodeId>, index: Option<usize>,
                     node: Node) -> CoreResult<NodeId>;
    pub fn remove_subtree(&mut self, id: NodeId) -> CoreResult<RemovedSubtree>;
    pub fn undo_remove(&mut self, subtree: &RemovedSubtree) -> CoreResult<IdRemap>;
    pub fn reparent(&mut self, id: NodeId, new_parent: Option<NodeId>,
                    index: Option<usize>) -> CoreResult<()>;
}
```

> **为什么不用现成的 ECS(如 hecs)**:场景图有强父子序和渲染序,SlotMap + 显式 children 向量最直接。如果未来对象数上十万,可换 `hecs`。
>
> **slotmap 的关键性质(已核实 1.1.1 源码)**:节点被移除后 slot 版本号单调递增,`KeyData` 字段私有 —— 安全 API **无法复原已删除的原 key**,不存在 `insert_with_id`。因此 `undo_remove` 恢复子树时**换发新 id** 并返回 old→new 重映射表(`IdRemap`),命令层负责把映射广播给历史栈(见 [03-UI框架层.md](03-UI框架层.md) §2)。对应测试:`remove_then_undo_remove_restores_subtree_exactly`(含"摘除期间插入占位节点"的真实编辑序列)。
>
> **serde 纪律**:Scene 全量 `Serialize + Deserialize`(含 slotmap serde),测试 `scene_serde_roundtrip_preserves_data_and_keys` 证明"既有句柄反序列化后继续有效" —— 这是分册六 §1.2"文档模型必须随时可完整序列化"铁律的验收。

## 4. 渲染管线:Vello 接入(sable-paint)

### 4.1 架构

> **⚠️ 2026 修正(以 [06-鲁棒性与技术债.md](06-鲁棒性与技术债.md) §6 为准)**:GPUI 仅在 **Linux** 上持有 wgpu device(可直接共享上下文);**Windows 上 GPUI 是 DirectX 11 原生渲染器**,Sable 画布需经"独立 wgpu 实例 + 跨 API 共享纹理(NT handle)"桥接,零拷贝或读回兜底,完整方案与代码见分册六 §6.2~§6.4。vello 侧代码在两个平台均不变(vello 只认 wgpu),变的只是结果纹理如何上屏。

**v0.1 落地的关键抽象:`PaintSink` —— 后端无关的绘制指令流**(`crates/sable-paint/src/sink.rs`)。上层(sable-canvas)只面向 `PaintSink` 编程,不感知后端;降级 = 换 Sink,场景图遍历代码零改动:

```
GPUI 帧循环
   │
   ├─ 面板 UI(GPUI 自己的渲染器绘制)
   │
   └─ Canvas Element::paint()                        [sable-canvas,规划]
        │
        ├─ scene.render_list()            // 收集可见节点(core 已实现)
        ├─ 视锥剔除(跳过屏幕外节点)
        ├─ 逐条指令发给 PaintSink:        // fill / stroke / fill_with_opacity
        │     ├─ VelloSink   → vello::Scene → render_to_texture   [gpu feature,骨架已落地]
        │     └─ VelloCpuSink → vello_cpu::RenderContext → RGBA8  [cpu feature,✅ 已落地]
        └─ 把结果纹理作为 quad 交给 GPUI 绘制
```

两个后端共享同一套数学(`style.rs`):`to_color` / `to_brush` / `linear_gradient` / `radial_gradient` / `to_stroke` / `with_opacity`;节点不透明度通过 `fill_with_opacity` 的默认实现**把 alpha 预乘进 Paint**,不走任何后端的图层混合 —— GPU/CPU 逐位一致(测试 `fill_with_opacity_multiplies_alpha_into_paint` 验证)。

### 4.2 画布 Element 实现

```rust
// sable-canvas(规划;渲染指令面已由 sable-paint 提供)
use gpui::*;
use kurbo::{Affine, BezPath, Stroke};
use sable_paint::prelude::*;
use sable_foundation::prelude::*;

pub struct SableCanvas {
    pub scene: Scene,                    // 数据在 sable-foundation(§3 下沉决策)
    pub viewport: Viewport,
    pub selection: Vec<NodeId>,
    // Vello 渲染器懒初始化(需要 GPU device 后创建),包 GpuGuard(分册六 §1.1)
    renderer: Option<vello::Renderer>,
}

impl SableCanvas {
    /// 场景图 → 绘制指令(经 PaintSink,后端无关)
    fn build_scene<S: PaintSink>(&self, sink: &mut S) {
        let vp = self.viewport.world_to_viewport();
        let visible_rect = self.visible_world_rect(); // 视锥剔除用

        for (id, node_xform) in self.scene.render_list() {
            let total = vp * node_xform;      // 视口变换 × 节点变换

            if let Some(p) = self.scene.path(id) {
                // 视锥剔除:包围盒与可见区不相交就跳过
                let bbox = total.transform_rect_bbox(p.path.bounding_box());
                if !bbox.intersect(visible_rect).is_zero_area() { /* 继续画 */ }

                // 不透明度 = 节点自身 opacity 沿父链累乘(render_list 时一并算好)
                let opacity = node_opacity_along_chain(id);
                if let Some(fill) = &p.fill {
                    sink.fill_with_opacity(fill, opacity, total, &p.path);
                }
                // ★ 形状描边:世界线宽原样(随缩放)—— 描边是文档内容的一部分
                if let Some(stroke) = &p.stroke {
                    sink.stroke(stroke, total, &p.path);
                }
            }

            // 选中态高亮属于覆盖层(overlay):屏幕等宽描边在这里才除以 zoom
            if self.selection.contains(&id) {
                if let Some(bbox) = self.scene.node_world_bbox(id) {
                    sink.stroke(
                        &StrokeStyle {
                            paint: Paint::Solid([0x4f, 0x9f, 0xff, 0xff]),
                            width: 1.5 / self.viewport.zoom,      // 覆盖层:屏幕恒定 1.5px
                        },
                        vp,
                        &kurbo::Rect::from(bbox).to_path(0.1),
                    );
                }
            }
        }
    }
}
```

> ### ★ 2026-10 落地决策:描边宽度语义修正(本节最重要的一处修正)
>
> 原文档示例把**形状描边**也写成 `Stroke::new(*width / self.viewport.zoom)`(屏幕等宽)。这是错的,**已修正**:
>
> - **形状自身的描边是文档内容**:用户设 2px 线宽,放大 4 倍后屏幕上就该是 8px。线宽以**世界坐标原样**传入(`StrokeStyle.width`),随节点变换与视口变换一起缩放 —— 与 Illustrator/Graphite 行为一致。`PaintSink::stroke` 的文档注释即如此约定("线宽为世界坐标宽度,屏幕等宽描边由上层除以 zoom 后传入")。
> - **`/zoom` 屏幕等宽只用于覆盖层(overlay)**:选中框、8 向控制柄、锚点手柄、网格线、参考线、橡皮筋预览 —— 这些是"界面",不是"内容",任何缩放下保持恒定屏幕像素宽(如选中框 1.5px、网格 0.5px)。
>
> 一句话:**内容除以 zoom 是 bug,覆盖层除以 zoom 是特性。** §9 验收清单对应两条:选中包围盒任意缩放下 1.5px(覆盖层)、放大形状描边跟随变粗(内容)。

```rust
pub fn grid_step_world(zoom: f64) -> f64 {
```

## 5. 命中测试:点选与框选

设计软件的"选择工具" = 命中测试 + 选中集管理(规划,落点 `sable-canvas::hit_test`;`Scene::node_world_bbox` / `render_list` 等 primitives 已在 core 就绪):

```rust
// sable-canvas/src/hit_test.rs(规划)
use kurbo::{Point, Shape};

impl SableCanvas {
    /// 点选:从顶层向下找第一个命中的节点
    /// tolerance: 世界坐标下的点击容差(屏幕 4px / zoom 得到)
    pub fn hit_test(&self, world_pt: Point, tolerance: f64) -> Option<NodeId> {
        // render_list 是底→顶,点选要反过来从顶→底
        for (id, xform) in self.scene.render_list().into_iter().rev() {
            let node = self.scene.node(id)?;
            if node.locked { continue; }
            let inv = xform.inverse();
            let local = inv * world_pt;  // 转到节点局部坐标

            let hit = match &node.content {
                NodeContent::Path(p) => {
                    // 1. 填充命中:点在路径内
                    let in_fill = p.fill.is_some() && p.path.contains(local);
                    // 2. 描边命中:点到路径的距离 < 线宽/2 + 容差
                    let near_stroke = p.stroke.is_some()
                        && distance_to_path(&p.path, local)
                           < p.stroke.as_ref().expect("已判 is_some").width / 2.0
                           + tolerance;
                    in_fill || near_stroke
                }
                NodeContent::Text(t) => {
                    text_layout_bbox(t).inflate(tolerance, tolerance).contains(local)
                }
                NodeContent::Group => false, // 组本身不响应,靠子节点
                NodeContent::Image(img) => img.rect.inflate(tolerance, tolerance).contains(local),
            };
            if hit { return Some(id); }
        }
        None
    }
}

/// 点到路径的最短距离(用 kurbo 的 flatten + 线段距离逼近)
fn distance_to_path(path: &BezPath, pt: Point) -> f64 {
    let mut min = f64::MAX;
    path.flatten(0.25, |el| {
        if let kurbo::PathEl::LineTo(p) = el {
            // 简化:只算到端点;完整版算到线段
            min = min.min(pt.distance(*p));
        }
    });
    min
}
```

> 生产级实现建议:路径距离用 kurbo 的 `segments()` + `Segment::nearest()` 精确求解;大量对象时加 R-tree(`rstar` crate)做空间索引,1 万对象下点选 < 0.1ms。

## 6. 文本渲染(Parley 接入)

```rust
// sable-canvas/src/text.rs(规划;parley 0.11)
use parley::{FontContext, LayoutContext, Layout};
use sable_foundation::scene::Rgba8;

pub struct TextPipeline {
    font_cx: FontContext,
    layout_cx: LayoutContext<Rgba8>,
}

impl TextPipeline {
    pub fn layout(&mut self, text: &str, font_size: f32, max_width: Option<f32>)
        -> Layout<Rgba8>
    {
        let mut builder = self.layout_cx.ranged_builder(&mut self.font_cx, text, 1.0, true);
        builder.push_default(parley::StyleProperty::FontSize(font_size));
        let mut layout: Layout<Rgba8> = builder.build(text);
        layout.break_all_lines(max_width);
        layout.align(max_width, parley::Alignment::Start, Default::default());
        layout
    }

    /// 把 parley 布局的字形逐个画进 vello scene
    pub fn draw(&mut self, vscene: &mut vello::Scene, layout: &Layout<Rgba8>,
                transform: kurbo::Affine) {
        for line in layout.lines() {
            for item in line.items() {
                let run = match item {
                    parley::PositionedLayoutItem::GlyphRun(r) => r,
                    _ => continue,
                };
                // 推荐直接用 vello::Scene::draw_glyphs(字形 run,GPU 字形缓存),
                // 比逐字形转路径快一个数量级;完整可运行示例参考 vello examples
                let _ = (run, transform);
            }
        }
    }
}
```

> 缓存纪律(分册六 TD-10):parley Layout 按 `(text_hash, width, font_version)` 缓存,属性面板打字才不卡。Scene 里的 `TextNode` 只存数据(`scene.rs` 注释:布局/塑形缓存归 canvas/text 管线)。

```rust
// sable-canvas/src/damage.rs(已实现;与原文差异:补 Default/is_dirty/clear)
pub struct DamageTracker {
    dirty_world: Vec<Rect>,   // 世界坐标脏区
}
impl DamageTracker {
    pub fn mark(&mut self, node_world_bbox: Rect) { self.dirty_world.push(node_world_bbox); }
    pub fn take(&mut self) -> Option<Rect> {
        // 合并所有脏区为一个包围盒;为空则本帧不渲染
        let mut merged: Option<Rect> = None;
        for rect in self.dirty_world.drain(..) {
            merged = Some(match merged { Some(acc) => acc.union(rect), None => rect });
        }
        merged
    }
    pub fn is_dirty(&self) -> bool { !self.dirty_world.is_empty() }
    pub fn clear(&mut self) { self.dirty_world.clear(); }
}
// 本帧无脏区 → 直接复用上一帧纹理,GPU 零工作
```

### 输入处理(缩放/平移/框选)

```rust
// input.rs(规划)—— 接 GPUI 事件
impl SableCanvas {
    pub fn on_scroll(&mut self, pt: Point, delta: Vec2, cx: &mut Context<Self>) {
        if cx.modifiers().control {
            // Ctrl+滚轮 = 以光标为锚缩放(也可换触控板 pinch)
            self.viewport.zoom_at(pt, if delta.y > 0.0 { 1.1 } else { 1.0 / 1.1 });
        } else {
            self.viewport.pan_by(delta);  // 普通滚轮 = 平移
        }
        cx.notify();
    }

    pub fn on_mouse_down(&mut self, world_pt: Point, cx: &mut Context<Self>) {
        match self.active_tool {
            Tool::Select => {
                if let Some(id) = self.hit_test(world_pt, 4.0 / self.viewport.zoom) {
                    if !cx.modifiers().shift { self.selection.clear(); }
                    self.selection.push(id);
                } else {
                    self.selection.clear();
                    self.rubber_band = Some(RubberBand::start(world_pt)); // 开始框选
                }
            }
            Tool::Pen => self.pen_state.click(world_pt),   // 见分册四 §3 钢笔工具
            _ => {}
        }
        cx.notify();
    }
}
```
